# 程式工作進度管理（本機版）

## 啟動方式
1. 安裝 Node.js 20 或更新版本。
2. 在此資料夾開啟終端機。
3. 執行：
   ```bash
   npm install
   npm run dev
   ```
4. 用瀏覽器開啟終端機顯示的網址（通常是 http://localhost:5173）。

## 功能
- 86 筆初始程式清單
- 新增、編輯、刪除、調整順序
- MD 自動排程：每日可投入 MD、週一至週五，同日可接續剩餘工作量
- 完成狀態、實際完成日、支數與 MD 完成率
- 每週預計與實際統計
- JSON 備份／還原、CSV 匯出
- IndexedDB 本機儲存，不需帳號或伺服器

## 注意
- 第 1 版預設未完成排程起算日為 2026-11-02，可在畫面上調整。
- 已完成的 24 筆資料保留由截圖轉錄的原日期；請核對資料正確性。
- 截圖中不易辨識的行數先留白；個別描述文字可能需校正。
- 此版本暫未加入國定假日。
- 每週「預計 MD」按程式預計完成週歸類；「實際 MD」按實際完成日歸類。
- 完成程式時會以當天日期記錄實際完成日，並固定當時排程日期。
- 請定期使用「備份」下載 JSON，避免清除瀏覽器資料造成遺失。

## 本次更新
- 已加入國定假日：2026-12-25、2027-01-01（不排程）。
- 每筆程式有「完成（回報）」及「實際完成（自己紀錄）」兩個獨立狀態。
- 實際完成狀態會記錄當天日期，週報的實際支數與實際 MD 依此統計。
- 可在每筆程式列按「＋」將新程式插入該筆之前；也可在新增表單由清單尾端新增。
- 可產生本週 e-mail 報告並複製內容到剪貼簿。
- 明細表字體已放大。

## 完成欄位統計規則（修正）
- 所有完成支數、完成率、實際支數、實際 MD、MD 達成率及週報統計，一律只看「完成（回報）」欄。
- 勾選「完成（回報）」時，實際完成日自動填入該程式的預計完成日；不使用今天日期。
- 「實際完成（個人備註）」只供自己記錄，不參與任何統計、週報或完成率計算。

## 實際完成日規則（再次修正）
- 原本已完成的 24 支程式：實際完成日沿用原表的預計完成日。
- 之後新勾選「完成（回報）」：實際完成日記錄當下系統日期。
- 「實際完成（個人備註）」只寫入獨立的個人紀錄日期，不會覆蓋實際完成日，也不參與統計。
- 升級時會自動將舊資料中已完成但缺少實際完成日的程式，以保留的原預計完成日補齊。

## 原始順序還原
- 啟動時會依照使用者最初提供的 86 筆截圖順序，重新排列原始程式。
- 後續新增、急插的非原始程式會暫時排在原始 86 筆之後；可再用每列的「＋」插入指定位置。

## Email 週報格式
- 點選「產生週報 e-mail」會開啟排版預覽，摘要及統計以 HTML 表格呈現。
- 在預覽頁按「複製表格內容」，再貼到郵件本文，可保留表格格式。

## Email 週報摘要表調整
- 郵件只保留「本週清查進度」一個摘要表格，不再附每週統計及完成明細表。
- 摘要表包含報告期間、總程式支數、已完成程式支數、應完成率（依排程）及實際完成率（依完成欄）。
- 實際完成率只以「完成」欄已勾選支數除以總程式支數計算；個人實際完成備註不參與計算。
- 應完成率以報告週五以前排程應完成的程式支數除以總程式支數計算。

## 每週完成率欄位
- 每週統計表新增「週結束日」、「應完成率（截至週五）」及「實際完成率（截至週五）」。
- 應完成率：截至該週週五，預計完成日不晚於週五的程式支數 ÷ 全部程式支數。
- 實際完成率：截至該週週五，已勾選完成且實際完成日不晚於週五的程式支數 ÷ 全部程式支數。

## 順序保留修正（第九版）
- 啟動時不再依原始 86 支重新排序，避免把使用者急插的新程式移到清單最後。
- 針對前一版已被錯誤移至尾端的 LBI8XFK、LBGDXFK，會在載入時自動移回原始第 25 支 LBHQD1K 之前，並保留兩支程式原本的相對順序。
- 之後新增或急插的程式會保留使用者在清單中指定的位置。

## 排序修正（第十版）
- 啟動時僅將原始截圖 86 筆依 seed 原始順序復原。
- 已知急插程式 LBI8XFK、LBGDXFK 放在原始第 25 筆 LBHQD1K 之前。
- 其他新增程式保留彼此順序並排在原始清單之後（若曾被舊版錯誤移到尾端，原插入位置無法從舊資料自動還原）。
- 修正初始化時重複儲存造成排序被舊陣列覆蓋的錯誤；排序結果只儲存一次。後續啟動不再重排使用者清單。
